AtariHelp.eu EMU-09 FIX341_TBXL_REAL_CLS_INPUT_CORE

Proc vznikl FIX341:
- FIX340 oddelil POWER BASIC a TBXL stav, ale stale nechaval ve hre stare capture handlery z FIX337/FIX339.
- Tyto stare handlery mohly sebrat klik/znak pred novou cestou, takze READY mohl svitit, ale prikaz CLS nemusel jit spolehlive do Turbo Basic interpreteru.

Co FIX341 meni:
- Stary FIX337 direct loader se pouzije jen k nahrani a relokaci TBXL do emulovane RAM.
- Hned po loadu FIX341 vypne stare TBXL flagy: fix337/fix339/fix340 = NO.
- currentXexName je zmenen na "T-BASIC XL 1.5 FIX341 / real command input core", aby stare regex/capture rutiny nevidely TBXL a nekradly klavesy.
- FIX341 si drzi vlastni aktivni flag fix341TbxlActive.
- FIX341 pridava vlastni PORTB ROM gate pro TBXL kod v A000/C000/D800/E400 oblastech.
- FIX341 pridava vlastni vstupni most pro tri cesty: CIOV GETREC/GETCHARS, KGETCH a CH/KBCODE/SKSTAT read.
- Tlačítko "POSLAT CLS PRES KLAVESY" neposila nic do RAM programu; jen posle C, L, S, RETURN stejnou FIX341 klavesovou frontou.

Co to neni:
- Neni to fake READY.
- Neni to screen paint.
- Neni to RAM program inject.
- Neni to oprava jen jedne hry.

Moje lokalni overeni:
- JS parser: vsechny script bloky projdou.
- Headless Chrome nacte FIX341 panel.
- Headless UI klik na start + CLS nevyhodi runtime chybu.
- Po headless kliknuti je fix341TbxlActive=YES, stare fix337/fix339 flagy=NO, currentXexName je T-BASIC XL 1.5 FIX341 a RAM $6132 obsahuje nahrany TBXL kod.

Limit overeni:
- Headless virtual-time v tomto prostredi nespolehlive rozjizdi requestAnimationFrame CPU smycku, proto se realne prijeti CLS musi potvrdit v APK/WebView.
